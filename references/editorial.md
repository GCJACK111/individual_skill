# 公众号图文组织与结语

## 按研究过程展开

文章主线为：**具体问题 → 方法各步及对应原图 → 实验如何检验、结果说明什么 → 一段结语**。从读者遇到的问题出发，逐步解释论文怎样解决，不逐段翻译摘要，也不把正文写成输入、输出、创新点的字段清单。

引言用一至几个短段落交代场景、现有困难及本文思路。之后按论文实际的机制、数据流或实验过程分节，不硬凑章节数。方法标题本身应带信息，例如“把建筑轮廓投到目标墙面”“合并重叠阴影，再计算受光面积”，避免每篇都用“模块一”“方法介绍”这类空标题。综述按其问题分类与证据组织，不强行编出一个模型流程。

每节先说明该步处理什么、怎样处理、产生什么，以及为什么需要它，再放直接对应的原图。技术路线图通常在整体思路之后；模型、机制、数据或任务示意图紧随相应步骤。图后用 1–3 句指出先看哪里、图中哪些部分对应正文、能看出什么。文字与图共同推进解释，避免先集中写完方法，再把图片堆在后面。

具体借鉴放在相关机制说明中，例如解释“先合并再计数”为什么能避免重叠区域重复计算。只写该篇真正支持的内容，不另外铺开一页学习清单。正文长度服从信息量；重复背景、重复图注和对同一机制的多次换词解释都应删去。

这套组织方式借鉴用户提供的公众号范例。参考的是段落、标题与图片之间的关系，不照搬截图中的研究对象、模块、作者、会议、指标或数字。

## 实验结果紧邻证据

先交代实验用了什么数据、比较了谁、指标衡量什么，再选最能说明核心贡献的结果展开。数值必须带上任务、条件、单位或统计口径；相对提升与百分点变化分清。正文可突出少数关键结果，原文表格仍完整保留全部模型行、指标列、子图、图例和脚注。

一组解释对应一组性能证据。先说这张图表在回答什么，再展示原图表，再解释关键差异与它支持的结论。消融、效率和迁移结果按实际问题衔接；不能用一个最好分数代表所有场景。图表多时可以续页，不能为了压缩页数而截掉对照或把表格缩成无法阅读的图片。

原文没有性能表时使用真实结果图；也没有定量证据就说明实际可用材料。综述保留其流程、比较表或元分析图，并明确那是文献汇总，不是作者训练了统一模型后的性能。

## 结语：一个准确的收束段

标题为 **“结语”**，默认一个自然段，约 **100–180 中文字、3–4 句**。这是写作尺度，不是硬字数限制。结语承接最后一组实验说明自然排版，不强制独占一页，也不拆成编号要点。

内容依次回答三个问题：

1. 本文提出或整理了什么方案，解决什么具体任务？
2. 最关键的机制是什么，怎样把问题与结果连起来？
3. 已呈现的证据支持这项工作有什么价值，适用到什么范围？

通常用“本文通过……完成……”“其关键在于……”“实验表明……，为……提供……”这样的直接陈述。不是每句都要套这些句式；保留具体对象和动词，删去重复修饰。实验数字前文已经讲清时，结语不必再抄一遍；只有某个数字决定结论时才保留它及必要条件。

精确性靠限定对象和证据，不能靠增加一长段免责声明。若结果仅来自所测场景，就把“在所测场景中”放在该主张内。不要把可视化效果写成已验证的物理准确性，不把模拟对照写成实测验证，不把逐时重新计算说成学到了时间依赖。

删除“值得深入研究”“具有广阔前景”“我们可以进一步考虑”等空泛收尾。没有原文证据时，不追加用户实验方案、迁移建议或未来畅想。结语应总结正文已有信息，不引入新机制、新结果或未经核验的因果解释；也不出现“AI 认为”或固定的“我们可以学到”栏目。

## 易懂但不改变技术含义

保留必要的技术名称，并紧接一句作用说明。读者应能复述输入资料、关键步骤、直接输出及必要的下游换算。只有理解机制需要时才加入数学，不堆完整推导；训练目标、参数或消融如果决定结果含义，应在对应位置说明。

- 用“给相关邻楼分配不同参考权重”解释注意力；没有来源验证时，不说“模型知道谁挡了太阳”。
- 用“预测区与参考区的重合程度”解释 IoU；区分平均 mIoU 与单一类别 IoU。
- R²、相关系数不是准确率。MAE/RMSE 说明单位；百分比误差说明分母、零值处理及聚合范围。
- 区分单位面积与总量、瞬时强度与累计能量、模拟与实测、区内验证与跨地区迁移。
- 方法名称对应原文：树模型、神经网络、几何算法、物理仿真和综述分类不能互相替代。

## 不能从结果直接推出的判断

- 总量误差近零，不证明每个位置都准确，正负误差可能抵消。
- 累计能量吻合，不证明逐时阴影边界准确，时空累加可能掩盖局部偏差。
- 两篇论文使用不同样本时，分数高低不能直接证明某个架构更好。
- 使用 Transformer、神经场或注意力，不自动证明技术更先进。
- 原文结果不等于在用户数据上已复现；注意力权重也不等于物理因果证据。

## 项目语境与来源

只有用户明确要求与个人项目比较时，才读取其当前研究说明与适用规则。通用版本只解释用户提供的论文，不默认存在共同的私人模型或实验计划。论文原生机制与针对用户任务的适配建议必须区分。

每篇重新写作、选图、核查原文坐标和数值。缺信息就写“原文未报告”或说明可访问材料的范围，不能填看起来合理的参数、年份或结果。不把未发布的用户研究设计放进通用技能包。
